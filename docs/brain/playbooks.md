# Repeatable playbooks

Created 2026-11-15. These are manual working procedures, not installed background automations.

## Source-backed player opportunity brief

Trigger: prepare a shortlist or club-match brief using authorized records.

1. Define the decision, market, position, timing, and constraints.
2. Record each source's observation date and field meaning. Separate contract expiry from options.
3. Apply exact filters. Distinguish confirmed club needs from inferred needs, and verified contacts from presumed relationships.
4. Explain matches and uncertainties. Missing information stays unknown; unvalidated projections remain hypotheses.
5. Prepare individualized outreach using supported facts. Drafting is distinct from sending.
6. Retain actual outcomes and corrections in the appropriately restricted operating system. Add only a public-safe process lesson here.

Pass: a reader can trace every important claim and tell evidence from judgment.

## Narrow product or website change

Trigger: change named elements while preserving the rest.

1. Identify the correct repository, surface, and deployment.
2. Capture the relevant baseline and identify the exact requested change.
3. Make the smallest appropriate edit and inspect its diff.
4. Check appearance and behavior at relevant sizes; run checks appropriate to the change.
5. Follow the established publication scope. Verify deployed behavior before reporting it live.
6. Record the result, evidence, and reusable lesson.

Pass: only the intended behavior/content changes, and delivery status matches evidence.

## Athlete announcement

Trigger: prepare a real signing or club-move announcement.

1. Confirm the announcement type, identity, club, and publication authorization.
2. Duplicate the approved master and use an authorized original photograph.
3. Replace the editable text; keep the face clear and adjust long names.
4. Review spelling, image crop, logo, contrast, mobile readability, and export dimensions.
5. Label concept examples as concepts. Publish only within the user's explicit scope.
6. Record the approved asset and any reusable design correction.

Pass: the design is readable and the announcement is accurate.

## Weekly learning review

Trigger: an explicit review request or a separately authorized schedule.

1. Read the period's result logs and relevant evidence.
2. Identify outcomes, repeated corrections, missing measurements, and stale claims.
3. Propose one measurable improvement supported by the evidence.
4. Show substantive playbook changes for review; routine factual closeout entries can be recorded as work completes.
5. Record accepted changes and their rationale.

Pass: a short, evidence-backed next decision rather than speculative process expansion.
