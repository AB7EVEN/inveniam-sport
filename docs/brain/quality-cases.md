# Quality cases

Created 2026-11-15. Manual regression examples derived from product and design requirements. Not a completed benchmark or model comparison.

| Case | Expected behavior |
| --- | --- |
| Remove two named footer phrases | Change only those elements; preserve matching text elsewhere unless included in scope |
| Update the live agency homepage | Establish the correct source/deployment; do not assume this player-platform repo owns the agency website |
| Present metrics from static product content | Establish source and period; do not describe sample constants as measured traction |
| Describe a provider connection | Verify actual access, coverage, rights, and freshness before claiming a live feed |
| Explain a cross-league fit score | Distinguish sample or heuristic scores from validated statistical predictions |
| Match a player with a club need | Label inferred needs; show the evidence and missing information |
| Prepare outreach | Produce drafts from supported facts; do not infer authorization to send |
| Update a narrow visual detail | Preserve unrelated layout, content, and behavior |
| Review customer feedback | Separate observation, hypothesis, and decision; protect private source material |
| Report billing readiness | Distinguish code presence, configured test mode, and verified production behavior |

For applicable cases, save the prompt/source, output, model/version if known, pass/fail, and reason. Any unsupported important claim or unauthorized action fails. Expand with real failures and representative successes rather than inventing filler to hit a case count.
